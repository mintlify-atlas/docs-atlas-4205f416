## Overview

Parkontrol uses **JSON Web Tokens (JWT)** for API authentication. All protected routes require a valid bearer token issued at login. Tokens are signed with a server-side secret and contain the user's identity and role.

Unprotected endpoints:
- `POST /api/auth/register`
- `POST /api/auth/login`

All other endpoints require a valid `Authorization` header.

## Getting a token

You receive a JWT in one of two ways:

- **Register** — create a new account via `POST /api/auth/register`. The response returns the created user, but not a token. You must log in separately to obtain one.
- **Login** — authenticate via `POST /api/auth/login` with your email and password. A successful response contains an `access_token`.

## Using the token

Include the token in the `Authorization` header of every request to a protected endpoint:

```bash
curl -X GET http://localhost:3000/api/reservations/activas \
  -H "Authorization: Bearer eyJhbGci..."
```

The token must use the `Bearer` scheme. Requests without a valid token, or with a malformed or expired token, will receive a `401 Unauthorized` response.

## Token expiry

Tokens expire **1 hour** after they are issued. After expiry, clients must re-authenticate via `POST /api/auth/login` to obtain a new token.

<Note>
  The frontend checks token expiry by decoding the `exp` claim in the JWT payload. If the token is expired, the user is treated as unauthenticated before any request is sent.
</Note>

## Roles

The JWT payload includes a `nombreRol` claim. Parkontrol defines two roles:

| Role | Description |
| --- | --- |
| `ADMINISTRADOR` | Full administrative access |
| `OPERADOR` | Operational access with restricted permissions |

Role-protected routes enforce these values server-side. Providing a valid token with an insufficient role results in a `403 Forbidden` response.

## Error responses

| Status | Meaning |
| --- | --- |
| `401 Unauthorized` | Token is missing, malformed, or expired |
| `403 Forbidden` | Token is valid but the user's role is not permitted for this route |

```json
{
  "statusCode": 401,
  "message": "Unauthorized"
}
```
