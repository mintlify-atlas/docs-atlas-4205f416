---
title: Invoicing
description: Create and manage electronic invoices and billing clients.
---

The invoicing system issues electronic invoices (`FacturaElectronica`) linked to a completed payment, and maintains a registry of billing contacts (`ClienteFactura`) that receive those invoices. Every invoice is tied to exactly one payment and one billing client, and carries a CUFE (unique electronic invoice identifier) along with an optional PDF URL.

## Billing clients

A `ClienteFactura` is the billing contact associated with an invoice — the party whose document number and email appear on the electronic invoice.

---

## POST /api/invoicing/clientes

Creates a new billing client.

```
POST /api/invoicing/clientes
```

### Request body

<ParamField body="tipoDocumento" type="string" required>
  Document type of the billing client (e.g. `CC`, `NIT`). Between 2 and 10 characters.
</ParamField>

<ParamField body="numeroDocumento" type="string" required>
  Document number of the billing client. Between 5 and 20 characters.
</ParamField>

<ParamField body="correo" type="string" required>
  Email address of the billing client. Must be a valid email format.
</ParamField>

### Response

Returns the created `ClienteFactura`. HTTP status `201 Created`.

<ResponseField name="id" type="number">
  Unique identifier of the billing client.
</ResponseField>

<ResponseField name="tipoDocumento" type="string">
  Document type.
</ResponseField>

<ResponseField name="numeroDocumento" type="string">
  Document number.
</ResponseField>

<ResponseField name="correo" type="string">
  Email address.
</ResponseField>

### Example request

```bash
curl -X POST http://localhost:3000/api/invoicing/clientes \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <token>" \
  -d '{
    "tipoDocumento": "CC",
    "numeroDocumento": "1023456789",
    "correo": "cliente@empresa.com"
  }'
```

### Example response

```json
{
  "id": 3,
  "tipoDocumento": "CC",
  "numeroDocumento": "1023456789",
  "correo": "cliente@empresa.com"
}
```

### Error cases

| Status | Cause |
| --- | --- |
| `400 Bad Request` | A required field is missing, the email is invalid, or a length constraint is violated |

## POST /api/invoicing/facturas

Creates an electronic invoice linked to an existing payment and billing client.

```
POST /api/invoicing/facturas
```

<Note>
  The payment identified by `idPago` must already exist. The billing client identified by `idClienteFactura` must also exist before calling this endpoint. The `enviada` flag is automatically set to `"N"` on creation.
</Note>

### Request body

<ParamField body="idPago" type="number" required>
  ID of the payment (`Pago`) this invoice is issued for.
</ParamField>

<ParamField body="idClienteFactura" type="number" required>
  ID of the billing client (`ClienteFactura`) who receives the invoice.
</ParamField>

<ParamField body="cufe" type="string" required>
  Unique Electronic Invoice Code (CUFE) assigned by the electronic invoicing provider. Up to 50 characters.
</ParamField>

<ParamField body="urlPdf" type="string">
  Optional URL pointing to the PDF version of the invoice. Up to 200 characters.
</ParamField>

### Response

Returns the created `FacturaElectronica`. HTTP status `201 Created`.

<ResponseField name="id" type="number">
  Unique identifier of the electronic invoice.
</ResponseField>

<ResponseField name="cufe" type="string">
  Unique Electronic Invoice Code.
</ResponseField>

<ResponseField name="urlPdf" type="string">
  URL of the invoice PDF, or `null` if not provided.
</ResponseField>

<ResponseField name="enviada" type="string">
  Indicates whether the invoice has been sent. `"N"` on creation; updated to `"Y"` by `PATCH /api/invoicing/facturas/:id/enviar`.
</ResponseField>

<ResponseField name="fechaCreacion" type="string">
  ISO 8601 timestamp of when the invoice was created.
</ResponseField>

<ResponseField name="pago" type="object">
  The payment this invoice is linked to.
  <Expandable title="pago fields">
    <ResponseField name="id" type="number">
      Payment ID.
    </ResponseField>
    <ResponseField name="monto" type="number">
      Amount charged.
    </ResponseField>
    <ResponseField name="fechaPago" type="string">
      ISO 8601 timestamp of the payment.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="clienteFactura" type="object">
  The billing client associated with the invoice.
  <Expandable title="clienteFactura fields">
    <ResponseField name="id" type="number">
      Billing client ID.
    </ResponseField>
    <ResponseField name="tipoDocumento" type="string">
      Document type.
    </ResponseField>
    <ResponseField name="numeroDocumento" type="string">
      Document number.
    </ResponseField>
    <ResponseField name="correo" type="string">
      Email address.
    </ResponseField>
  </Expandable>
</ResponseField>

### Example request

```bash
curl -X POST http://localhost:3000/api/invoicing/facturas \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <token>" \
  -d '{
    "idPago": 17,
    "idClienteFactura": 3,
    "cufe": "abc123cufe456def789",
    "urlPdf": "https://storage.example.com/facturas/17.pdf"
  }'
```

### Example response

```json
{
  "id": 8,
  "cufe": "abc123cufe456def789",
  "urlPdf": "https://storage.example.com/facturas/17.pdf",
  "enviada": "N",
  "fechaCreacion": "2025-03-15T14:22:00.000Z",
  "pago": {
    "id": 17,
    "monto": 12000.00,
    "fechaPago": "2025-03-15T14:20:00.000Z"
  },
  "clienteFactura": {
    "id": 3,
    "tipoDocumento": "CC",
    "numeroDocumento": "1023456789",
    "correo": "cliente@empresa.com"
  }
}
```

### Error cases

| Status | Cause |
| --- | --- |
| `400 Bad Request` | A required field is missing or fails validation |
| `404 Not Found` | No payment exists with the given `idPago`, or no billing client exists with the given `idClienteFactura` |

## PATCH /api/invoicing/facturas/:id/enviar

Marks an invoice as sent by setting its `enviada` flag to `"Y"`.

```
PATCH /api/invoicing/facturas/:id/enviar
```

### Path parameters

<ParamField path="id" type="number" required>
  ID of the electronic invoice to mark as sent.
</ParamField>

### Request body

No request body is required.

### Response

Returns the updated `FacturaElectronica`. HTTP status `200 OK`.

<ResponseField name="id" type="number">
  Unique identifier of the invoice.
</ResponseField>

<ResponseField name="cufe" type="string">
  Unique Electronic Invoice Code.
</ResponseField>

<ResponseField name="urlPdf" type="string">
  URL of the invoice PDF.
</ResponseField>

<ResponseField name="enviada" type="string">
  Updated to `"Y"` after this call.
</ResponseField>

<ResponseField name="fechaCreacion" type="string">
  ISO 8601 timestamp of when the invoice was originally created.
</ResponseField>

### Example request

```bash
curl -X PATCH http://localhost:3000/api/invoicing/facturas/8/enviar \
  -H "Authorization: Bearer <token>"
```

### Example response

```json
{
  "id": 8,
  "cufe": "abc123cufe456def789",
  "urlPdf": "https://storage.example.com/facturas/17.pdf",
  "enviada": "Y",
  "fechaCreacion": "2025-03-15T14:22:00.000Z"
}
```

### Error cases

| Status | Cause |
| --- | --- |
| `404 Not Found` | No invoice exists with the given `id` |

## GET /api/invoicing/facturas/pago/:idPago

Retrieves the electronic invoice associated with a specific payment, including the linked payment and billing client.

```
GET /api/invoicing/facturas/pago/:idPago
```

### Path parameters

<ParamField path="idPago" type="number" required>
  ID of the payment whose invoice you want to retrieve.
</ParamField>

### Response

Returns the `FacturaElectronica` for the given payment, with `pago` and `clienteFactura` relations populated. HTTP status `200 OK`.

<ResponseField name="id" type="number">
  Unique identifier of the electronic invoice.
</ResponseField>

<ResponseField name="cufe" type="string">
  Unique Electronic Invoice Code.
</ResponseField>

<ResponseField name="urlPdf" type="string">
  URL of the invoice PDF.
</ResponseField>

<ResponseField name="enviada" type="string">
  `"Y"` if the invoice has been sent, `"N"` otherwise.
</ResponseField>

<ResponseField name="fechaCreacion" type="string">
  ISO 8601 timestamp of invoice creation.
</ResponseField>

<ResponseField name="pago" type="object">
  The payment this invoice is linked to.
  <Expandable title="pago fields">
    <ResponseField name="id" type="number">
      Payment ID.
    </ResponseField>
    <ResponseField name="monto" type="number">
      Amount charged.
    </ResponseField>
    <ResponseField name="fechaPago" type="string">
      ISO 8601 timestamp of the payment.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="clienteFactura" type="object">
  The billing client associated with the invoice.
  <Expandable title="clienteFactura fields">
    <ResponseField name="id" type="number">
      Billing client ID.
    </ResponseField>
    <ResponseField name="tipoDocumento" type="string">
      Document type.
    </ResponseField>
    <ResponseField name="numeroDocumento" type="string">
      Document number.
    </ResponseField>
    <ResponseField name="correo" type="string">
      Email address.
    </ResponseField>
  </Expandable>
</ResponseField>

### Example request

```bash
curl http://localhost:3000/api/invoicing/facturas/pago/17 \
  -H "Authorization: Bearer <token>"
```

### Example response

```json
{
  "id": 8,
  "cufe": "abc123cufe456def789",
  "urlPdf": "https://storage.example.com/facturas/17.pdf",
  "enviada": "Y",
  "fechaCreacion": "2025-03-15T14:22:00.000Z",
  "pago": {
    "id": 17,
    "monto": 12000.00,
    "fechaPago": "2025-03-15T14:20:00.000Z"
  },
  "clienteFactura": {
    "id": 3,
    "tipoDocumento": "CC",
    "numeroDocumento": "1023456789",
    "correo": "cliente@empresa.com"
  }
}
```

### Error cases

| Status | Cause |
| --- | --- |
| `404 Not Found` | No invoice exists for the payment with the given `idPago` |

```json
{
  "statusCode": 404,
  "message": "No existe factura para el pago con id: 17",
  "error": "Not Found"
}
```
